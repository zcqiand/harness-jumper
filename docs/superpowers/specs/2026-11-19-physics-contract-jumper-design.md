# harness-jumper 物理契约即关卡——设计文档

> 2026-11-19 人裁收口（brainstorming 产出，方案 A）。书三 ch10《平台跳跃》配套仓，Godot 4.7 首个完整仓。

## 意图与为什么

把 harness-jumper 骨架写成完整可玩的平台跳跃。突出点只有一个：**物理契约即关卡**——每关是一份「物理参数规约+平台布局」的契约实例，双闸认证保证它不只是手摆的方块堆：①**可达性判定器**在加载时用该关参数表模拟真实跳跃物理，断言从出生点出发每个平台都可达，不可达关卡当场拒载并指出第一个够不到的平台；②**运行时落点断言**核对实际跳跃行为与参数表承诺（峰值高度≤理论界、落点必在平台面）。玩家可感知=**换关即换物理世界**：同一段代码，低重力月球关、高弹力关跑出完全不同的手感，关卡带「已认证」徽章。ch10 教学核心全部是这套机制的构成件：物理规约=契约本体，碰撞/检查点断言=时序纪律，对象池=落地尘土粒子的复用手法，关卡配置化=换关换主题的日常操作。「跳多高」不再手感调参，而是参数表说了算——断言不是法官而是认证机构（maze 合法幽灵同族 DNA，对象从走线换成关卡）。

## 目标

- **完整可玩平台跳跃**：横版跳跃（起跑→跳台→检查点→终点旗），方向键/WASD 移动+空格跳，触屏左右/跳按钮；坠落=回最近检查点，通关=结算
- **关卡契约**：`{name, theme, gravity, jump_speed, move_speed, spawn, goal, platforms, checkpoints}`（骨架 flat 键保留只增不改；spawn/goal/checkpoints/theme/move_speed 新增可选键，缺省有默认）
- **可达性判定器（认证第一闸）**：关卡加载时以参数表驱动**与运行时共用同一运动学积分函数**做离散模拟（固定 dt），BFS 传播「从出生点可达的平台集合」，有平台不可达→拒载+报平台序号；认证通过的关卡发 `certified` 徽章
- **运行时断言（认证第二闸）**：每次跳跃实测峰值高度 ≤ 理论界 `jump_speed²/(2·gravity)`（小容差）、落地落点必在平台面；违例=拒绝本局成绩（防御性，正常玩法不可触发）
- **检查点时序断言**：检查点必须按序激活（跳序=断言红），激活中最近者即坠落重生点
- **主题配置化**：`theme` 字段映射调色板（背景/平台/角色色），换主题=换 JSON 字段；关卡集含至少一个物理差异 showcase 关（月球低重力）
- **对象池**：落地尘土粒子从固定池复用（ch10 术语落点，池上限+复用断言）
- **本地成绩册**：每关最快通关时间+通过状态，读侧守卫前置（家族三仓同款纪律）

## 方案取舍

- **突出点三选一**（2026-11-19 人裁）：A 物理契约即关卡 / B 轨迹承诺线（预测抛物线 ghost 叠实际轨迹）/ C 检查点计时速通 → **A 胜出**。B 偏仪表盘、玩法本体无新机制；C 与 maze 幽灵竞速撞型连做两仓计时赛。A 是 ch10「调参从玄学变工程」的极致形态：关卡=物理规约的实例化，且认证机构模式在 maze 已打磨过，GDScript 重写正好实证 ch10 章钩子「范式不挑引擎」

## 关键设计裁定（builder check 前我方裁定，用户可否决）

1. **同一运动学模块双消费**：水平/垂直速度积分写成纯函数模块（输入=状态+参数+输入向量+dt，输出=新状态），游戏运行时每帧调用、可达性判定器模拟调用同函数——认证的物理=玩家玩到的物理，结构上不可能分叉。渲染层用 CharacterBody2D 承载，速度积分结果喂给它
2. **可达性=离散模拟 BFS，不自闭式解析解**：dt=1/60 步进模拟跳跃直至落地，采样平台边缘若干起跳点；平台间可达=存在一个起跳点使模拟落点命中目标平台顶面。抛物线×矩形的解析解数学优雅但易错且与运行时分叉——模拟直白且天然同代码。模拟超时上限（如 3s 游戏时间）防悬空平台死模拟
3. **运行时断言只抽两条**：峰值高度界+落点在平台面。不做逐帧轨迹 diff（那是 snake 行车记录仪的路线，本仓保持「关卡认证」单一焦点）；断言违例按防御性处理——正常玩法不可触发，触发即成绩不入档
4. **检查点按序激活**：顺序错=时序断言红（本局成绩不认可，可继续玩）。检查点兼坠落重生点，家族「断言是认证机构」气质的时序面
5. **关卡契约向后兼容**：骨架 flat 键（name/gravity/jump_speed/platforms）语义与校验不变；spawn/goal/checkpoints/theme/move_speed 为新增可选键，缺省值让旧契约照样可玩
6. **测试零三方依赖**：headless 自建 runner 跑 GDScript 断言（assert_eq/assert_true 薄壳），不引 GUT；`--headless` 下场景树可用但不开窗口
7. **物理参数含 move_speed**（水平速度上限），骨架没有——新增键；摩擦不做（平台跳跃手感用瞬时速度+小加速度模型，摩擦是 soccer/赛车概念，ch10 point 表里的「摩擦参数」以加速度/减速度形式落进参数表）
8. **平台=单向（只碰顶面）**（builder check 收口）：所有平台可从下方/侧面穿过，仅下落穿越顶面时着陆。这让 Q3「认证器要不要模拟中途碰撞」结构上消解——空中无阻挡，飞行=纯运动学积分（共享模块一份代码），落地=「下落中穿越平台顶面」一个事件，判定器与运行时同语义；关卡设计空间=垂直向上攀登+跳下不受阻，装饰平台随便摆
9. **空中水平操控允许，认证器输入策略=人类可直接执行的策略集**（builder check 收口）：{全程按满左, 全程按满右, 中性不按}×平台边缘起跳点采样——按满一个方向是玩家真实可复现的输入，认证不验人类做不到的技巧跳；可达=三策略之一能落上目标平台
10. **掉落是可达图的边**（builder check 收口）：BFS 两类转移=跳跃边（模拟）+行走/坠落边（水平走离平台边缘→垂直下落命中下方平台顶面）；关卡不必严格向上
11. **v1 单一固定跳跃**（builder check 收口）：无可变高度跳/土狼时间/跳跃缓冲——认证动作集与运行时严格一致，峰值断言语句单一（跳多高=jump_speed²/(2·gravity)，规约说了算正是突出点）
12. **运行时固定步长**（builder check 收口）：运动学积分只在 `_physics_process`（Godot 固定 60Hz）跑，dt 与判定器同为 1/60——认证物理=运行物理在时间轴上也不分叉；渲染插值归视觉层
13. **玩家碰撞盒=代码全局常量**（builder check 收口）：尺寸不入关卡契约（契约管世界不管身体）；落点判定以碰撞盒底边中心落在平台顶面 x 区间内为准
14. **计时锚=首次输入**（沿用家族 maze 裁定 9 先例）：待命不起表，首输入起表，速通反应延迟不计入成绩

## 视觉方向（builder 落地）

「极简积木」风：纯色块平台+圆角角色+主题色大面积铺底，认证徽章=关卡卡上的对勾小盾牌。个性在「同一代码不同世界」——月球关整个色板翻冷色+粒子漂浮。克制不花哨。

## 状态机与语义裁定

1. 状态机：选关 → 出生 → running → checkpoint(激活动画) → finished（结算：时间+断言全绿徽章）→ 返回选关
2. 坠落死亡：回最近检查点，无检查点则回出生点；坠落数计数不判负（平台跳跃惯例）
3. 断言违例：运行时断言红=本局成绩不入档+结算页红字标违例项（与 maze 拒收文案同气质）
